# 质量、测试与可观测性

> 状态：已确认（2026-09-14）

## 1. 质量原则

- 正确性优先于吞吐量。
- 已知失败必须可检测、可解释和可恢复。
- 没有基线不做性能结论。
- 没有原始记录不对外给出性能数字。
- 测试必须验证行为和不变量，而不是只验证函数被调用。
- 先定位瓶颈，再用最小改动优化，最后做回归验证。

## 2. 测试分层

### 单元测试

范围：

- 状态机合法迁移。
- 匹配规则、队列和取消。
- 幂等键和重复请求。
- 数据序列化和协议校验。
- 连接会话状态转换。

要求：

- 每个核心模块有独立测试目标。
- 失败用例覆盖空值、重复、越界、超时和非法状态。
- 测试不依赖真实网络时使用受控替身。

### 集成测试

范围：

- Gateway -> Match -> Room 的 brpc 调用。
- Redis/MySQL 存储和恢复。
- Kafka 发布、消费和重复消费。
- WebSocket 到内部服务的消息链路。

要求：

- 使用 Docker Compose 启动真实依赖。
- 每个测试有独立数据命名空间或清理策略。
- 测试结束不能遗留容器、端口和临时数据。

### 端到端测试

核心流程：

1. 两个玩家登录。
2. 双方进入匹配。
3. 匹配成功并进入同一房间。
4. 开始游戏并发送输入。
5. 一方断线并在宽限期内重连。
6. 对局结束并完成结算。
7. 查询战绩、排行榜和回放。

### 长稳和故障测试

- 持续运行连接建立、断开和重连。
- 服务进程重启。
- Redis、MySQL 或 Kafka 暂时不可用。
- 节点停止和恢复。
- 消息重复、延迟和积压。
- 连接风暴和突发请求。

## 3. Sanitizer 和静态检查

| 工具 | 用途 | 触发时机 |
|---|---|---|
| ASan | 越界、UAF、泄漏 | 单元测试、内存相关改动、合并前 |
| TSan | 数据竞争和锁问题 | 并发模块、连接和房间状态改动 |
| UBSan | 未定义行为 | 核心模块合并前 |
| clang-format | 代码格式 | 每次提交前 |
| clang-tidy | 常见缺陷和风格问题 | CI 和关键模块 |
| 编译警告 | 发现潜在问题 | 所有构建必须开启并保持干净 |

## 4. 可观测性三要素

### 结构化日志

日志必须包含：

- 时间、级别、服务名、版本和实例 ID。
- `request_id`、`session_id`、`player_id`、`room_id`、`match_id`（存在时）。
- 事件名称、结果、耗时和错误码。
- 不包含 Token、密码、私钥和完整敏感载荷。

### 指标

首批指标：

- 当前连接数、连接建立/断开速率。
- HTTP/WebSocket 请求数、QPS 和错误率。
- RPC 调用数、延迟直方图和超时。
- 匹配人数、等待时长和匹配成功率。
- 活跃房间数、房间创建/销毁速率。
- 重连次数、成功率和 Session 过期数。
- Redis/MySQL 调用延迟和失败率。
- Kafka 生产速率、消费速率、Lag 和重试次数。
- 进程 CPU、内存、FD 和线程数。

### 链路追踪

优先追踪：

- 登录。
- 进入/取消匹配。
- 创建/加入房间。
- 断线重连。
- 结算和排行榜更新。

## 5. SLO 和容量目标

初始目标见项目章程。调整目标必须满足：

- 有正式 ADR。
- 说明原目标无法达到的技术原因。
- 不掩盖真实回归。
- 不修改历史压测结果。

每次压测报告至少包含：

- 代码版本和构建类型。
- 机器 CPU、内存和内核版本。
- 服务实例数、连接数和房间数。
- 测试持续时间、think time 和请求分布。
- QPS、p50、p95、p99、最大值和错误率。
- CPU、内存、FD、网络和中间件指标。
- 原始日志、脚本和必要的火焰图。
- 已知限制和不能代表的生产条件。

## 6. 性能优化流程

```text
固定环境
  -> 建立基线
  -> 复现瓶颈
  -> 收集证据
  -> 提出一个假设
  -> 做最小改动
  -> 回归测试
  -> 对比数据
  -> 保留或回退
```

禁止：

- 没有基线就优化。
- 同时修改多个变量后归因。
- 只展示优化后数据。
- 通过减少请求、关闭校验或改变测试负载制造“提升”。
- 用平均延迟代替尾延迟。

## 7. 发布门禁

每次阶段发布前必须：

- 全量测试通过。
- ASan/TSan 按影响范围通过。
- 数据库迁移可重复执行并说明回退。
- 配置和依赖版本固定。
- README 和 Runbook 可复现。
- 关键指标存在且有面板。
- 已知问题已记录，不隐藏。
- 演示脚本实际运行成功。
