# 项目文档索引

## 文档用途

本目录是项目的长期知识库和协作入口。任何 AI 开始任务前，必须按顺序阅读根目录
`CLAUDE.md`、本索引、项目章程、架构、路线图和当前任务。

聊天记录不是项目真相。重要结论必须写回仓库文档、ADR 或 devlog。

## 文档维护规则

1. 需求变化更新 `00-charter.md` 和 `02-roadmap.md`。
2. 服务边界、数据归属和跨服务调用变化更新 `01-architecture.md`，并新增 ADR。
3. 技术选型、放弃备选方案和不可逆决定写入 `adr/`。
4. 单次任务的范围和验收写入 `TASKS.md`。
5. 每天完成的工作、问题和结果追加到 `devlog.md`。
6. 测试、性能和故障结论写入 `04-quality-and-observability.md` 或对应报告。
7. 接口和消息格式变化先更新 `05-api-and-data.md`，再修改代码。
8. 发现文档冲突时停止实现，由项目所有者确认后再继续。
